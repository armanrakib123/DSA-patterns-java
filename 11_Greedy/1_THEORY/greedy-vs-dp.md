# Greedy vs Dynamic Programming (গ্রিডি বনাম ডিপি)

## The Core Difference (মূল পার্থক্য)

| Feature | Greedy Algorithm | Dynamic Programming (DP) |
| :--- | :--- | :--- |
| **Approach** | শুধুমাত্র বর্তমান ধাপের সেরা চয়েসটি নেয়। | সব সম্ভাব্য চয়েস দেখে এবং সেরাটি বেছে নেয়। |
| **Future Impact** | ভবিষ্যতের কথা চিন্তা করে না। | ভবিষ্যতে কী হতে পারে তা মাথায় রাখে। |
| **Speed** | অনেক ফাস্ট ($O(N)$ বা $O(N \log N)$)। | তুলনামূলক ধীর ($O(N^2)$ বা তার বেশি)। |
| **Complexity** | সহজ লজিক এবং ছোট কোড। | জটিল লজিক এবং স্টেট ম্যানেজমেন্ট। |
| **Optimality** | গ্যারান্টি নেই সব সময় সঠিক হবে। | সবসময় গ্লোবাল অপ্টিমাল রেজাল্ট দেয়। |

## Decision Making
- **Greedy:** আপনি একটি রাস্তা বেছে নিলেন এবং আর পেছনে ফিরে তাকালেন না। 
- **DP:** আপনি সব রাস্তায় হাঁটার সম্ভাবনা চেক করলেন এবং যেখানে সবচেয়ে কম খরচ বা বেশি লাভ, সেটি বেছে নিলেন।

## When to move from Greedy to DP?
যদি আপনি দেখেন যে বর্তমান ধাপের সেরা সিদ্ধান্তটি নিতে গিয়ে আপনি ভবিষ্যতে কোনো একটি বড় সুযোগ মিস করছেন, তবে বুঝবেন গ্রিডি কাজ করবে না। তখন আপনাকে ডাইনামিক প্রোগ্রামিং-এর সাহায্য নিতে হবে।

ইন্টারভিউতে গ্রিডি প্রবলেমগুলো প্রায়ই ডিভি দিয়েও সলভ করা যায়। কিন্তু আপনি যদি গ্রিডি লজিক প্রমাণ করতে পারেন, তবে আপনার কোড অনেক বেশি পারফরম্যান্স দিবে যা Software Company ইন্টারভিউয়াররা পছন্দ করেন। ⚖️⚙️🧠✅
